# Project documentation

This directory contains technical, operational, and submission documentation.

Suggested documents:
- `architecture.md` — component boundaries and data flow.
- `workflow.md` — end-to-end user and review workflow.
- `api/` — API reference and examples.
- `data_dictionary.md` — entities, fields, status values, and provenance.
- `model_card.md` — intended use, limitations, training/evaluation details, and risks.
- `benchmark_methodology.md` — held-out test protocol and metric definitions.
- `privacy_security.md` — data protection, access, retention, and incident handling.
- `deployment.md` — reproducible deployment and configuration.
- `user_guide.md` — reviewer instructions.
- `adr/` — architecture decision records.
- `proposal/` — proposal and challenge materials, if approved for inclusion.

Keep documentation aligned with actual implementation. Mark proposed behavior as planned, and distinguish measured results from targets. Do not include secrets, private data, or unsupported claims of validation.
