# Architecture decision records

Record important architecture decisions as short, version-controlled documents.

Each record should include:
- **Title and status** — proposed, accepted, superseded, or rejected.
- **Context** — the problem and constraints.
- **Decision** — what was chosen.
- **Alternatives** — options considered and why they were not selected.
- **Consequences** — operational, security, cost, and maintenance implications.
- **References** — related issues, code, or documentation.

Create an ADR for decisions with meaningful long-term consequences, such as storage/retention strategy, model-serving approach, identity and access control, benchmark design, or official-source retrieval. ADRs do not replace current operational instructions.
